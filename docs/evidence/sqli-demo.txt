== 2. ROOT CAUSE
   The statement text is built from user input, so input can change the grammar of the statement (quote, UNION, comment).
   Escaping lists or blacklists do not fix this; the database must receive the statement and the data separately.

== 4. WHY THE FIX WORKS
   * With bound parameters the statement is parsed first; the input can only ever be a value, never SQL.
   * Server-side prepared statements (PDO::ATTR_EMULATE_PREPARES=false) also refuse stacked statements: see the A7-A9 result in section 1.
   * Defence in depth held even while the code was vulnerable: column privileges, RLS and the missing UPDATE/DELETE grants capped the damage.

RESULT: vulnerability demonstrated, then no longer exploitable
