---- 2d. Reading of the evidence ----
 WHAT HAPPENED   A session using the grants_app account, from the web container's network and with an application name the
                 web application never uses, ran outside any HTTP request: it listed the accounts, claimed an officer identity,
                 tried to move money in pieces and to erase its tracks, awarded 1.00 through the one open door, and forged an
                 audit event that frames a researcher.
 WHEN / WHO      Times in 2a and 2c (UTC). Account: grants_app (the web service credential). Claimed identity: the officer account.
 RESOURCES       users (read), proposals (read), one proposal and its call balance (changed through record_decision), audit_events (one forged row).
 CONTROLS THAT HELD
   * No password hash and no audit read (permission denied, logged by the server with the statement text).
   * No partial award: direct INSERT on decisions and UPDATE of the balance refused (finding F01 remediated).
   * Audit trail intact: UPDATE, DELETE and TRUNCATE on audit_events refused even for the application account.
   * Every refusal appears in the PostgreSQL log with user, database, time and the exact statement.
 CONTROLS THAT FAILED / WEAK
   * Identity is self-asserted (app.user_id): a stolen credential can act as any officer (observation O02).
   * The application account can write audit events, so a forged event is indistinguishable by content (observation O03);
     it is detectable only by what it lacks: no request id and no source address (query 2b).
   * The award itself is a legitimate-looking decision.record event; only 2b and 2c reveal that it was not made through the web application.
 CORRECTIVE ACTIONS
   1. Rotate the grants_app password now and treat the secrets/web.env file as exposed; review who could read it.
   2. Reverse the award with an authorized correction procedure and record the reason (decisions are final by design).
   3. Give audit writing its own account and service (O03) and bind the actor to the request (O02: signed actor token or a per-session role).
   4. Alert on anomaly query 2b and on 'application_name' values not used by the application.
   5. Tighten pg_hba.conf to the web container address and add pgaudit for statement-level coverage.
